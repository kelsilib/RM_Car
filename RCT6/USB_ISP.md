## 1. 这根线怎样完成下载

实际路径是：电脑USB-A → 支持数据的A转C线 → 板载CH340的Type-C口 → USART1 → STM32系统Bootloader → Flash。源码先编译成HEX，再写入板子；不是把C文件直接复制到板子上。

| 原理图接口 | 接到哪里 | 本次用途 |
|---|---|---|
| J1 Type-C | 板载CH340K，UART连PA9/PA10，DTR/RTS经电路控制RESET/BOOT0 | 串口ISP下载；下载后同一口看日志/发文字指令 |
| J2 Type-C | MCU原生USB，PA11/PA12 | 当前应用没有实现USB设备协议，本次不选此口 |

不能只凭接口外形或左右位置判断。先看实物丝印、CH340芯片位置及板卡版本；不确定时提供主板正反面照片。看到“未知USB设备”不能直接认定CH340驱动坏了，也可能插到另一个C口。

本路径不使用ST-Link，不需要给当前应用添加USB协议，也不能当作USB DFU。SWD仍保留供以后的断点/单步调试；串口下载和终端没有这些调试功能。

## 2. 首次连接

1. 先断开外部5V、电机/舵机动力和其他模块，只让裸主控通过一根USB数据线供电。原理图中两个USB口VBUS与排针5V同网，不能未经处理并联电源。
2. 用支持数据的A转C线直连电脑和CH340对应C口；厂商建议首次不用扩展坞。仅充电线无法枚举串口。
3. Windows右键“开始” → “设备管理器” → “端口(COM和LPT)”，记录插入后新增的CH340串口及实际COM号。助手也可代查设备；不要照抄资料截图中的COM8。
4. 若没有正常COM口，先检查数据线和接口，再检查驱动。厂商配套资料含CH340K驱动，也提供[沁恒官网下载入口](https://www.wch.cn/search?t=all&q=CH340)。已有驱动能正常识别时不用重复安装；需要安装时再确认来源和操作。

板卡注意事项写明BOOT0/BOOT1已有下拉，无需为这套自动下载流程另加跳线帽。不要根据其他板子的教程随意短接；不能自动进入下载时先核对实物版本和配置，再按该版本资料排查。

## 3. 选对固件

在本目录打开PowerShell：

```powershell
.\build.ps1
.\board.ps1 -Mode Verify
```

前者编译，后者只检查电脑上的ELF/HEX/BIN，不连接设备。纯文档修改不要求重编译；下载前仍需确认选中当前构建产物。

- 本工程下载文件：`build/rm_rct6.hex`，HEX自带地址。
- 若使用支持BIN的其他工具，`build/rm_rct6.bin`的基地址是`0x08000000`；FlyMCU步骤优先用HEX。
- 不选仓库上级旧C8/TB6612产物、PC测试EXE，也不选专门测试用的PS2启用构建。
- 首次保持默认运动禁用、标定关闭、`RM_PS2_WIRED=0`。这一步验证主控启动和日志，不要求电机、手柄或机械臂接好。

## 4. 厂商FlyMCU操作路径

本机资料包根目录为`C:/Users/fakel/Downloads/rct6/1779183725162378/`。打开其中`4.开发软件/4.ISP烧录软件/FlyMcu.exe`，再按以下顺序操作。关闭其他占用该COM口的终端或下载工具。

| 顺序 | 界面位置 | 设置/观察 |
|---|---|---|
| 1 | `STMISP`页 → `搜索串口` → `Port` | 选择刚刚确认的CH340实际COM号 |
| 2 | `bps` | 使用板卡专用配置图中的115200；通用PDF的230400是另一截图示例 |
| 3 | 程序文件旁的浏览按钮 | 选择当前工程`build/rm_rct6.hex`，核对完整路径 |
| 4 | 编程选项 | 勾选“编程前重载文件”“校验”“编程后执行”；“连续烧录模式”不勾 |
| 5 | 左下角ISP进入方式 | 选择`DTR的低电平复位,RTS高电平进BootLoader`，这是板卡厂商给出的设置 |
| 6 | 选项字节区 | “编程到FLASH时写选项字节”保持不勾，不随意设置读保护/选项字节 |
| 7 | `读器件信息` | 在上述设置下尝试读取；结合芯片丝印核对F103高密度系列、256KB Flash。工具可能只显示系列名，不能只凭系列名确认具体封装/容量 |
| 8 | `开始编程` | 确认目标及文件后执行，检查写入、校验和运行日志；失败时保存完整报错再排查 |

配置图还勾了“使用RamIsp”，但右侧是STM32F40xx示例日志，未证明本板必须使用此选项。先读取实际器件并以工具的支持结果为准，不能用示例日志认定本板已识别成功；不要为使示例一致而主动解除读保护、全片擦除或改选项字节。

厂商资料说明有自动BOOT/RESET电路。正常流程由下载软件控制，不要求一直手动把BOOT0拉高。2026-10-25用户已按该FlyMCU设置成功连接和下载；这不证明其他串口库的控制线时序也相同，不要把FlyMCU界面里的高/低电平文字直接翻译成某个串口库的布尔值。

## 5. 下载后看日志

1. 确认写后校验通过，并让程序从Flash运行；关闭FlyMCU，释放COM口。
2. 日志终端使用**115200、8数据位、无校验、1停止位、无流控（8N1）**。ISP阶段的UART配置由下载工具管理；若用CubeProgrammer UART，其帮助列的是8位数据加偶校验，不能沿用到应用日志终端。
3. 在本目录运行现有终端入口，下面的COM7必须换成实物端口：

```powershell
.\board.ps1 -Mode Terminal -Port COM7
```

只抓日志时可改用`-Mode Monitor -Port COM7`。两者都不是烧录命令；不要同时打开占用同一个COM口。

默认无手柄、无驱动时，应按[BRINGUP.md](BRINGUP.md)检查启动文字、禁动状态和缺项。终端指令及回复格式见[CONSOLE.md](CONSOLE.md)。日志证明程序运行到对应路径，不能代替GPIO波形、电机运动或无线失联验收。

串口打开/关闭时某些驱动会改变DTR/RTS，可能影响自动下载电路。现有脚本在打开前设置这两线不主动切换，但实物表现仍待验证；必要时在确认BOOT状态后按RST，不能靠反复切换控制线猜测。

## 6. 失败时先查什么

| 现象 | 先检查 |
|---|---|
| 插线后没有新增COM口 | 数据线、CH340对应C口、电脑USB口、设备管理器驱动状态 |
| 有COM口但打开失败 | 是否选错端口，FlyMCU/终端是否同时占用 |
| 能开COM但读不到STM32 | 左下角DTR/RTS方式、板卡版本、BOOT/RESET状态、主控供电；CH340枚举成功不等于MCU握手成功 |
| 报读保护、要求解除保护或全片擦除 | 停下记录实际提示；解除保护可能擦除原有内容，不作为普通下载失败的默认处理 |
| 校验失败 | 目标型号/容量、所选HEX、线缆/供电及完整日志；不能当成下载完成 |
| 校验通过但没有应用日志 | 程序是否从Flash启动、下载工具是否释放COM、终端8N1设置、BOOT0/复位状态 |

现有`board.ps1 -Mode ReadTarget`使用ST-Link/OpenOCD，不适用这条USB串口ISP路径。它的`Check`包含ST-Link工具检查，不能将“缺ST-Link”当成A转C下载不可用。

本机已找到随CubeIDE安装的`STM32_Programmer_CLI.exe`，帮助提供UART连接、DTR/RTS、下载和校验选项。助手可在实物接好后代查COM号并准备命令行下载；实际BOOT进入方式需先验证，不把“工具存在”当成已烧录成功。插拔线、确认接线及必要按键由用户操作。
