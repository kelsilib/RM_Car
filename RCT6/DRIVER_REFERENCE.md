## 2. 两处资料笔误

- 串口表`Sheet1!G14`将`mline`写成减速比。STM32示例第33～44行和IIC表将两者分开：`mline`是磁环线数，`mphase`是减速比。当前程序和说明采用交叉核对后的含义。
- 串口表`Sheet1!E42`在PWM示例里误写`spd`。同行命令名、官方PDF和STM32构造函数都使用`pwm`；当前程序继续发送`$pwm:...#`，范围±3600。

只在本工程说明差异，厂商原始文件保持不变。

## 3. 配置回读怎样查看

资料中的配置输出使用以下普通文本格式，每项以换行结束；这里展示格式占位符，不是用户驱动的实测数值：

```text
Motor_Version:%s
Motor_type:%d
Dead_Zone:%d
Pulse_Line:%d
Pulse_Phase:%d
wheel_diameter:%.3f
P:%.3f I:%.3f D:%.3f
```

允许整行前后空格。当前只解析前六项；PID行和其他提示行跳过。配置字段区分大小写，不能改成想当然的名称。

在完成无电机负载接线核对、烧录r4并打开CH340终端后，依次发送：

```text
driver read
driver info
driver safety
```

先等驱动回复，再发第二条；如果字段尚未收全，可再次发送`driver info`查看。`driver read`在停车且没有电机传输故障时才允许，它先清除旧配置记录，再请求`$read_flash#`。`reply OK query_queued`只说明主控接受了查询，不是驱动ACK。`driver info`仅查看主控已收到的数据，不发送配置命令、不写Flash、不修改verified。

返回字段的含义：

| 字段/位值 | 怎么读 |
|---|---|
| `fields` | 收到了哪些合法字段；按下面六个位相加 |
| `0x01` / `version` | 固件版本；最多16个ASCII字母、数字或`._-` |
| `0x02` / `mtype` | 电机类型；记录0～4，0也不代表运行配置已正确 |
| `0x04` / `deadzone` | 驱动PWM死区参数；记录0～3600 |
| `0x08` / `mline` | 磁环线数；记录0～65535 |
| `0x10` / `mphase` | 减速比参数；记录0～65535 |
| `0x20` / `diameter_mm` | 驱动Flash轮径，单位mm，显示三位小数 |
| `age_ms` | 距离最近一个合法配置字段的时间；不是每个字段分别的年龄 |

`fields=0x3F`仅表示六项都收到，不表示电机参数匹配、查询事务已确认或整车通过验收。没有对应位时，显示的0或`none`不能作为真实参数使用。范围检查只是解析保护，例如允许记录0或很大的轮径以方便排查，不能据此认定这些数值适合本车。重复收到非法字段值会清除该项；超长、控制字符或截断行会丢弃。每次重新查询先清空，避免把上次完整记录当作本次回复。协议无查询序号，仍不能排除延迟回复。

配置行缓冲64字节，最多接收63个可打印字符；支持CR、LF或CRLF。字节间隔超过50ms后旧半行作废。`$...#`帧里的文字不会按配置行使用。`driver reply`仍保留最近一条未知`$...#`帧，普通配置行改由`driver info`查看；两者都不会刷新电机健康时间，仍只有合法MAll可以刷新。

## 4. 速度反馈与速度指令分开核对

官方STM32和树莓派示例明确：`$MSPD:a,b,c,d#`是mm/s浮点反馈。旧代码把SPD指令的±1000限制也套到反馈上，可能把合法的超调或手转反馈判成坏包。本次移除这项错误限制，仍检查普通十进制、有限数和数值过大等异常。

发送的`$spd:M1,M2,M3,M4#`仍限制±1000；`$pwm:...#`仍限制±3600，通道顺序不变。2026-11-02用户补充确认SPD为轮缘mm/s，不是轴rpm，受wdiameter影响；当前生产`speed_unit=RM_SPEED_MM_S`。这一更新来自控制指令的新依据，不能倒推为10月26日就已从反馈注释确认。

r6行驶许可增加轮径一致性检查：驱动`wheel_diameter`字段必须已收到、有限且为正，并与`radius_m×2000`按三位小数相同。当前主控80mm，因此驱动保存67mm示例值、缺字段或非法值都不能生成行驶速度。恢复匹配后仍须回中、松START再新按；不会自动写驱动Flash或修改人工验收记录。单轮PWM标定不做速度/轮径换算，继续由独立保护等前置条件限制。

r8的driver safety回复spd_unit=mm_s、command_loss=hold_last、timeout_config=unsupported、software_stop_verified=0/1和diameter_match=0/1。软件停车记录按SELECT/电脑stop检查填写，轮径字段按实际回读比较。重新配置或更换驱动后停车重新read/info，接着核对当前轮径。r6的independent_stop诊断保留在对应历史报告。

## 5. 哪些参数继续保留、哪些需要实物核对

主控继续采用用户确认的80mm轮径、0.040m半径、原CAD轮心距和凹口车头。驱动Flash的`wdiameter`是另一份配置，需要在实际驱动上读回后人工核对是否为80mm；不照抄厂商示例67mm，也不自动写入。

电机类型由实际编码器和AB接法确定，磁环线数11及减速比30为旧交接候选值，实际参数与轮向仍需核验。r8按用户本轮选择使用软件停车验收，生产software_stop_verified和其他验收默认false，标定及PS2默认关闭。

**`FourWay_Motor_STM32.hex`是四路驱动板的固件，不能烧进RCT6主控。** 本工程给RCT6使用的文件只有当前构建的`build/rm_rct6.hex`（或正确基地址的BIN），下载说明见[USB_ISP.md](USB_ISP.md)。本次未更新任何设备固件。

r4修改与检查结果见[历史报告](reports/DRIVER_ALIGNMENT_2026-10-26.md)，当前r6见[驱动收尾报告](reports/DRIVER_FINALIZATION_2026-11-02.md)。

## 6. 驱动没有超时停车，怎样处理

本节记录r6/r7曾采用的独立停车门禁。2026-11-04用户明确选择SELECT/电脑stop人工架空联调，当前r8按第7节执行。

驱动内部保持末值是已知行为，不能再把旧`driver_failsafe_verified`理解为一个等待勾选的驱动能力。r6已将字段改名`independent_stop_verified`，并保持false。仅把单位设对、看到编码器更新、发出stop或重启主控，都不能填写这项。

后续外部保护至少要覆盖：主控程序停止/失去调度、主控复位、主控TX到驱动RX的命令线路断开；即使驱动仍不断回传MAll，也必须能进入安全状态。人工急停开关保留，但仅有人工开关不能证明自动失联保护。仅由主控喂一个独立心跳也不能单独覆盖TX断线，需要保护方案能观察到驱动端实际接收命令的丢失，或具备同等有效的独立停止依据。

可准备的硬件位置是“电机动力分支→额定值合适的独立切断器件→四路驱动VIN”，由独立监视/急停电路控制。这里仅定义功能要求，尚未确定切断器件、电流/电压额定值、延迟或控制针；不虚构一根主控GPIO就称已实现。硬件还需定义失电默认状态、恢复后禁止自动重新上电、接头断线行为及实测停止效果。底盘动力和七台承重舵机供电分开处理，避免切底盘时让机械臂意外卸力坠落。

在该方案落实并测试前，只做断开电机负载的UART/配置查询，普通行驶和单轮标定都不开放。主控看门狗可以帮助重启，但不能把断开的TX接回来，也不能替这块无超时驱动制造出硬件停车能力。

## 7. 当前r8的软件急停验收

用户2026-11-04明确使用PS2 SELECT或电脑stop，无须新增驱动超时命令。r8将验收字段改为software_stop_verified，保持false等待实测。两条路径撤销行驶/标定许可并生成PWM0，重新回中并新按START才重新许可。人工看护、四轮架空，带动力保持UART接好，主控停机或TX断线时先隔离动力再排查。测试步骤见[今晚联调](TONIGHT_BRINGUP.md)。
