# 当前底盘软件交付范围

已完成的软件范围是STM32F103RCT6、四轮麦克纳姆、亚博四路智能串口驱动、PS2和七路MG995逐路手动控制。2026-11-04用户确认S1是承载K210的升降台，S2～S7共六路供机械臂编号控制，见[机械臂控制说明](ARM_CONTROL.md)。K210回传后三条红绿蓝灯带亮灯仍未实现；机械臂的实际参数、供电和机构验收仍待补齐。

设备记录为旧r1已完成主控单板启动和version/config检查，当前r9尚待下载。PS2、电机和舵机待实测，本轮按用户指定SELECT/电脑stop开展人工架空联调，见[今晚入口](TONIGHT_BRINGUP.md)。K210回传和灯带仍待开发。

2026-10-26物料更新：用户指定1台K210、7台MG995、1块四路驱动板，STM32从电源板供电；此前四台SG90方案仅保留历史。当时完成[排线安排](WIRING_PLAN.md)，保留PS2，并预留K210 USART3、七路TIM3/TIM4 PWM和灯带控制接口，尚未实现新功能。11月1日已补七路PWM代码，供电、信号门限和具体关节分工继续待确认，默认仍禁用。

同日补充：用户转述算法侧称K210为“CANMV”，已按CanMV/K210线索更新排线说明。具体开发板版本和运行固件仍待实物/程序核对，不继续假定Maix Bit或KD233；STM32 USART3 PB10/PB11与七路舵机安排保持不变。

同日后补照片：商品参数标CanMv K210S，实物印创乐博、CanMV K210，已按该系列更新[排线表](WIRING_PLAN.md)。外接座P7/TX接主控PB11，P6/RX接PB10，5V/GND由电源板独立支路提供；接口角色来自实物丝印，逻辑电平、运行固件、FPIOA/UART配置和回传协议仍未实测或核对完整。K210型号不再整体列为未知，尚未取得的PCB修订资料与算法源码继续保留为缺项。

## 已实现的软件

| 功能 | 入口 | 说明 |
|---|---|---|
| 参数检查和缺项说明 | `src/board_config.c` | 集中填写尺寸、轮序、限速和验收记录；能说明缺哪些项 |
| 遥控读取 | `src/remote_ps2.c` | GPIO时序、模拟模式确认、摇杆和START/SELECT转换 |
| 正常底盘控制 | `src/mecanum.c`、`src/chassis_app.c` | 前后、横移、旋转、死区、加减速、合成限速、四轮比例限幅 |
| 安全和模式切换 | `src/safety.c` | 上电禁动、独立新鲜度检查、故障停车、回中及新START解锁 |
| 设备恢复 | `target/main.c` | 停车时重发上传开关和PS2设置，恢复后不自动解锁 |
| 驱动串口协议 | `src/motor_uart.c` | 速度/PWM命令、四轮映射、严格收包、坏包/半包/超长和计数边界处理 |
| 驱动配置只读回读 | `src/motor_uart.c`、`src/console.c` | read_flash普通文本六字段接收，driver read/info查询；不写参数、不自动验收 |
| 单轮标定 | `src/calibration.c` | 独立许可、幅度/时长约束、一次只动一接口、异常取消，默认关闭 |
| 电脑文字指令 | `src/console.c` | 查询状态、手柄、计数、输出、电压和缺项；停车与受限标定 |
| 板级支持 | `target/` | 72MHz时钟、双UART接收、SWD保留、启动/中断/链接脚本 |
| 电脑辅助工具 | `board.ps1`、`tools/` | 终端、单次指令、日志解释、工具检查、ARM产物检查 |
| 七路机械臂手动控制 | `src/arm_config.c`、`src/arm_control.c`、`target/board_servo.c` | L2模式与底盘互锁、逐路许可、限位限速、故障冻结和只读查询；默认关闭 |
| 可重复构建和软件测试 | `build.ps1`、`tests/` | 真实ARM固件与PC模拟测试，代码注释使用中文白话 |

亚博驱动负责四个电机的编码器采集和轮速PID，主控不重复实现。主控只把车体目标变成四轮目标并监督通信。

## 不连接主板也能做的事

在本目录打开PowerShell：

```powershell
.\build.ps1 -Test
.\build.ps1
.\board.ps1 -Mode Test
.\board.ps1 -Mode Verify
```

依次是C逻辑/模拟主循环测试、ARM固件构建、日志检查工具测试、固件地址与向量检查。这些命令都不连接或控制实物。`-Rebuild`可以强制重新编译。

代码阅读从TEST_INDEX.md开始，串口指令见CONSOLE.md，r9升降台独立键与当前验证见[机构控制说明](ARM_CONTROL.md)，r8软件停车检查见[该轮报告](reports/SOFTWARE_STOP_2026-11-04.md)。

## 底盘尚待实测的部分

当前待实测为装配尺寸、轮序/方向、电机参数、PS2电气/无线行为、SELECT/电脑stop和UART/GPIO波形。r8按用户选择进行人工看护、四轮架空联调，默认行驶与标定保持关闭，K210/机械臂缺项继续各自处理。

这些值没有用模拟数据冒充。软件模块已经提供相应配置和观察入口；按实测结果填写、重新构建，再做硬件调试。首次可先按[USB_ISP.md](USB_ISP.md)烧录默认禁动固件，不必等整车资料齐全。

## 已有资料，不需要重新找整包

- STM32F103RCT6原理图、厂商UART示例、双C口说明、FlyMCU下载软件及串口ISP配置图已经在本机。
- 用户提供的官方PS2资料已核对，来源及附件冲突见[PS2_REFERENCE.md](PS2_REFERENCE.md)。还缺实物接线、电平及失联行为的测试结果，不是缺整份PS2协议。
- 亚博四路驱动资料与单位依据已具备，4个JGB37-520电机、30:1和11PPR来自旧交接候选，实物配置/计数仍需验证。当前用户选择SELECT/电脑stop软件急停，默认验收标志待测。
- 原交接记录写有Maix Bit、4个拟用SG90、YB-MP01-V1.0和三条各50mm灯带。当前采用7台MG995；K210按最新创乐博CanMV K210实物与K210S商品参数图识别，本机旧KD233示例不适用。其余规格和接线继续对照实物，不把旧方案当成已验收事实。

## 另外待办A：K210回传后亮三条红绿蓝灯带

**已确认：** K210识别程序已有，UART回传尚未做；亮的是三条灯带。当前RCT6固件尚未包含K210接收或灯带驱动。

| 还需要提供什么 | 用来决定什么 |
|---|---|
| 现有K210识别源码及依赖、运行固件版本、开发板和摄像头型号 | 按最新CanMV线索核对实际固件/API，在已有识别流程中增加回传；旧MaixPy/KD233示例不代替当前程序 |
| 创乐博K210S配套原理图/串口例程、现有算法程序与固件版本 | 外接P7/TX、P6/RX和5V/GND位置已有图片依据；继续核对电平、FPIOA映射、实际占用及回传协议，不套其他板程序 |
| 三条灯带的商品链接或手册、标签、接线/驱动板照片 | 确定普通恒压或可寻址类型、额定电压/电流和开关/数据驱动，不能让GPIO直接给灯带供电 |
| 确认仍按原比赛规则，或提供新版规则及变化 | 确定Tag ID到颜色的对应、什么时候允许识别、保持多久、何时清零、断联后如何处理 |

旧交接按Tag36H11：红510/514/519/530，绿533/542/547/562，蓝568/573/579/582；有效识别后各色独立锁存到本局结束，新局清零，准备阶段不点灯。这是待确认的规则依据，本轮仅确认了灯的种类，不能据此宣称全部比赛规则已再次确认。

**后续开发顺序：** 读取现有识别代码和官方硬件/固件资料 → 写清双方通信协议 → 给K210增加发送 → STM32完整收包、校验和白名单判断 → 更新本局灯带状态 → 按实际灯带做输出适配。

因为目前没有回传，不要求用户先提供不存在的报文。协议需要双方一起定义，至少说明帧边界、长度、消息类型、Tag ID、轮次/会话、序号、校验与重同步；波特率和字节序写入同一份协议后再开发。收到任意字节不能直接点灯。

软件验收覆盖半包/粘包、乱码/坏校验、无效ID、重复包、旧局包、K210重启与断联，且收包不能阻塞底盘停车检查。实际颜色、电平和灯带供电留到上板验证；逻辑测试通过不能代替灯带已亮的记录。

## 机械臂：已实现的软件与剩余工作

七台MG995的TIM3/TIM4 PWM、逐路手动控制、PS2按键、限位限速和故障冻结已实现。用户确认S1为承载K210的升降台、S2～S7共六路供机械臂编号控制；模型没有完整七关节装配，不编造关节名称、行程或自动动作。配置仍全零，`RM_ARM_WIRED=0`，本轮没有连接或驱动舵机。

| 还需要提供什么 | 用来决定什么 |
|---|---|
| 每个舵机的实际型号、手册/商品链接和线序 | 确认位置舵机还是连续旋转，使用PWM还是总线，以及额定电压和信号要求 |
| 后续每路对应的关节/夹爪、完整装配和需要的动作 | 编号手动控制已完成；进一步确定关节名称、转动方向和自动动作流程，末端坐标控制另需连杆尺寸与关节结构 |
| 各关节允许范围、初始姿态和机械干涉位置 | 分路设限，避免上电自动扫到两端；端点只能在低负载校准后作为已验证值 |
| 核对故障保持策略、底盘隔离及防坠落措施 | 按键已分配：L2进入、方向左右选路、新START许可、R2加右Y调整；故障保持最后已写脉宽，需核对机构能否采用这种策略 |
| YB-MP01对应版本的各轨持续/峰值电流资料、实际舵机稳压支路图 | 核对七路MG995同时动作/保持的供电能力与压降；优先预留独立舵机支路，不能从插针数量推断输出电流 |

**后续顺序：** 补齐本批舵机电气资料和独立供电 → 核对底盘隔离、防坠落及初始姿态 → 按安全调试流程逐路标定脉宽、方向和速率 → 只启用已确认的一路 → 多路联调。完整机构确定后再设计自动动作或坐标控制。资料不齐时保持输出关闭，不默认所有MG995都支持50Hz、0.5～2.5ms或0～180°；细项见[ARM_CONTROL.md](ARM_CONTROL.md)。
