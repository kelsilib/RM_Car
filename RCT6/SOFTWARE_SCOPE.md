# 当前底盘软件交付范围

已完成的软件范围是STM32F103RCT6、四轮麦克纳姆、亚博四路智能串口驱动和PS2。2026-10-23用户新增两个独立待办：K210回传后点亮三条红绿蓝灯带、机械臂控制。两项尚未实现，资料缺项和实施顺序列在本文后半部分。

当前设备状态：主板已到手、尚未接电脑。K210已有识别程序，但还没有回传；用户已确认亮灯指原交接中的三条红绿蓝灯带。不能将“底盘软件已补齐”理解为这些新增功能也已完成。

## 已实现的软件

| 功能 | 入口 | 说明 |
|---|---|---|
| 参数检查和缺项说明 | `src/board_config.c` | 集中填写尺寸、轮序、限速和验收记录；能说明缺哪些项 |
| 遥控读取 | `src/remote_ps2.c` | GPIO时序、模拟模式确认、摇杆和START/SELECT转换 |
| 正常底盘控制 | `src/mecanum.c`、`src/chassis_app.c` | 前后、横移、旋转、死区、加减速、合成限速、四轮比例限幅 |
| 安全和模式切换 | `src/safety.c` | 上电禁动、独立新鲜度检查、故障停车、回中及新START解锁 |
| 设备恢复 | `target/main.c` | 停车时重发上传开关和PS2设置，恢复后不自动解锁 |
| 驱动串口协议 | `src/motor_uart.c` | 速度/PWM命令、四轮映射、严格收包、坏包/半包/超长和计数边界处理 |
| 单轮标定 | `src/calibration.c` | 独立许可、幅度/时长约束、一次只动一接口、异常取消，默认关闭 |
| 电脑文字指令 | `src/console.c` | 查询状态、手柄、计数、输出、电压和缺项；停车与受限标定 |
| 板级支持 | `target/` | 72MHz时钟、双UART接收、SWD保留、启动/中断/链接脚本 |
| 电脑辅助工具 | `board.ps1`、`tools/` | 终端、单次指令、日志解释、工具检查、ARM产物检查 |
| 可重复构建和软件测试 | `build.ps1`、`tests/` | 真实ARM固件与PC模拟测试，代码注释使用中文白话 |

亚博驱动负责四个电机的编码器采集和轮速PID，主控不重复实现。主控只把车体目标变成四轮目标并监督通信。

## 不连接主板也能做的事

在本目录打开PowerShell：

```powershell
.\build.ps1 -Test
.\build.ps1
.\board.ps1 -Mode Test
.\board.ps1 -Mode Verify
```

依次是C逻辑/模拟主循环测试、ARM固件构建、日志检查工具测试、固件地址与向量检查。这些命令都不连接或控制实物。`-Rebuild`可以强制重新编译。

代码阅读从`TEST_INDEX.md`开始；串口指令用法见`CONSOLE.md`。PS2官方资料对应关系见`PS2_REFERENCE.md`，最新修复与实际检查结果见`reports/PS2_REFACTOR_2026-10-23.md`；原软件交付和修复记录保留为历史版本。

## 底盘尚待实测的部分

这里剩的是实测数据和上板验证：实际轮径/轴距/轮距、轮序与方向、驱动速度单位和电机配置、接收器电气与无线断联行为、独立停车保护、串口和GPIO时序。默认值中的未知项保留禁动，标定默认也关闭。

这些值没有用模拟数据冒充。软件模块已经提供相应配置和观察入口；按实测结果填写、重新构建，再做硬件调试。首次可先按[USB_ISP.md](USB_ISP.md)烧录默认禁动固件，不必等整车资料齐全。

## 已有资料，不需要重新找整包

- STM32F103RCT6原理图、厂商UART示例、双C口说明、FlyMCU下载软件及串口ISP配置图已经在本机。
- 用户提供的官方PS2资料已核对，来源及附件冲突见[PS2_REFERENCE.md](PS2_REFERENCE.md)。还缺实物接线、电平及失联行为的测试结果，不是缺整份PS2协议。
- 亚博四路智能驱动已有官方协议资料。4个JGB37-520电机、12V/333rpm、30:1和11PPR来自原交接记录；实际驱动配置、速度单位、轮向和计数仍需核验。
- 原交接记录写有Maix Bit、4个拟用SG90舵机、YB-MP01-V1.0电源板和三条各50mm灯带。除本轮确认的三色灯带用途外，型号、规格和接线应对照当前实物；不把旧方案当成已验收事实。

## 另外待办A：K210回传后亮三条红绿蓝灯带

**已确认：** K210识别程序已有，UART回传尚未做；亮的是三条灯带。当前RCT6固件尚未包含K210接收或灯带驱动。

| 还需要提供什么 | 用来决定什么 |
|---|---|
| 现有K210识别源码及依赖、运行固件版本、开发板和摄像头型号 | 在已有识别流程中增加回传，确认使用的MaixPy/API和真实识别结果字段 |
| K210实际引脚图、已占用接口/接线照片 | 选择独立UART及电平适配，避开电机USART2和下载/终端USART1；未确认前不直接指定新引脚 |
| 三条灯带的商品链接或手册、标签、接线/驱动板照片 | 确定普通恒压或可寻址类型、额定电压/电流和开关/数据驱动，不能让GPIO直接给灯带供电 |
| 确认仍按原比赛规则，或提供新版规则及变化 | 确定Tag ID到颜色的对应、什么时候允许识别、保持多久、何时清零、断联后如何处理 |

旧交接按Tag36H11：红510/514/519/530，绿533/542/547/562，蓝568/573/579/582；有效识别后各色独立锁存到本局结束，新局清零，准备阶段不点灯。这是待确认的规则依据，本轮仅确认了灯的种类，不能据此宣称全部比赛规则已再次确认。

**后续开发顺序：** 读取现有识别代码和官方硬件/固件资料 → 写清双方通信协议 → 给K210增加发送 → STM32完整收包、校验和白名单判断 → 更新本局灯带状态 → 按实际灯带做输出适配。

因为目前没有回传，不要求用户先提供不存在的报文。协议需要双方一起定义，至少说明帧边界、长度、消息类型、Tag ID、轮次/会话、序号、校验与重同步；波特率和字节序写入同一份协议后再开发。收到任意字节不能直接点灯。

软件验收覆盖半包/粘包、乱码/坏校验、无效ID、重复包、旧局包、K210重启与断联，且收包不能阻塞底盘停车检查。实际颜色、电平和灯带供电留到上板验证；逻辑测试通过不能代替灯带已亮的记录。

## 另外待办B：机械臂控制

当前没有机械臂输出实现，不能从“4个舵机、SG90够了”的旧讨论推导出最终动作范围。

| 还需要提供什么 | 用来决定什么 |
|---|---|
| 每个舵机的实际型号、手册/商品链接和线序 | 确认位置舵机还是连续旋转，使用PWM还是总线，以及额定电压和信号要求 |
| 机构照片或视频、每路对应的关节/夹爪、需要的动作 | 确定通道分工、转动方向、手动操作与自动动作流程；若要按末端坐标运动，另需连杆尺寸和关节结构 |
| 各关节允许范围、初始姿态和机械干涉位置 | 分路设限，避免上电自动扫到两端；端点只能在低负载校准后作为已验证值 |
| PS2按键分配、失联/急停时希望保持还是卸力 | 避免覆盖底盘START/SELECT含义；防止卸力后机构或载荷坠落 |
| YB-MP01对应版本的各轨持续/峰值电流资料、实际供电图 | 核对四路舵机同时动作的供电能力与压降；不能从插针数量推断输出电流 |

**后续开发顺序：** 确认接口和动作定义 → 通道配置、每路限位及速度限制 → 初始姿态和故障策略 → 手动调试/动作状态机 → 单舵机低负载校准 → 多关节联调。资料不齐时保持输出关闭，不默认所有舵机都支持50Hz、0.5～2.5ms或0～180°。

## 当前先提供哪些

1. **首次USB下载：** 主板正反面照片，能看清两个C口、CH340、BOOT/RST和芯片丝印；准备支持数据的A转C线。连接后实际COM号和驱动状态可以由助手读取。
2. **K210和亮灯开发：** 现有识别程序、固件版本、灯带/驱动资料，并确认是否沿用上面的比赛规则；UART协议由后续开发共同补齐。
3. **机械臂开发：** 舵机型号、机构照片/动作要求，以及电源板规格；实测限位可在准备好受限调试代码后逐路填写。
4. **底盘运动验收：** 按[CONFIG_PENDING.md](CONFIG_PENDING.md)补轮几何、轮序、驱动参数和实测记录。这些资料不影响先烧录默认禁动版本。
