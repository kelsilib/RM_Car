# 电脑串口指令说明

这些指令走板载CH340连接的USART1，115200、8N1、无流控。电机协议仍走USART2，两边不能混接。

没有主板时，先运行 `.\build.ps1 -Test`、`.\board.ps1 -Mode Test` 和 `.\board.ps1 -Mode Verify`。它们只在电脑上运行，不需要连接设备。

有板后，`board.ps1 -Mode Terminal -Port COM7` 可以打开交互终端，把COM7换成实际端口。工具先收齐你输入的一整行，再发给主控；输入`exit`只退出电脑终端。单次指令可用 `board.ps1 -Mode Command -Port COM7 -Command 'ps2'`。2026-10-25用户在COM5的Terminal中取得version/config完整reply回复，确认这两条查询的实际双向收发；其他指令和Command模式仍按实际测试记录，不能自动认定全部通过。详见[单板实测记录](reports/USB_ISP_2026-10-25.md)。

## 可以发送哪些指令

| 指令 | 做什么 | 怎么读结果 |
|---|---|---|
| `help` | 列出指令 | 不控制电机 |
| `version` | 查看软件编号 | 当前默认版`rm_rct6-bench-20261104-r9-safe`，PS2只读版`rm_rct6-bench-20261104-r9-ps2`；均尚未烧录 |
| `status` | 当前状态和不能动的原因 | state、inhibit沿用周期日志，另外显示cal阶段 |
| `ps2` | 查看手柄 | fwd/left/yaw/right_y为千分比，buttons为按下位图；不是m/s或实测关节位置 |
| `arm` | 只读查看机械臂状态 | 模式、许可、所选编号、最后写入脉宽、缺项和故障；这条命令不使能舵机 |
| `servo 1`～`servo 7` | 只读查看一路舵机配置 | 限位、起始脉宽、速率、方向和最后写入值；不能用它改参数或动作 |
| `counts` | 最近MAll的四个原始计数 | 按M1/M2/M3/M4排列；不是左前/右前/左后/右后顺序 |
| `config` | 查看缺项和标定限制 | issues各位见下表；不允许在终端修改验收标志 |
| `output` | 最近生成的四通道目标 | mode=spd时按已确认的mm/s；mode=pwm时是厂商PWM参数 |
| `battery` | 最近收到的电压 | millivolts除1000得到V；seen=0表示还没收到电压包 |
| `driver voltage` | 请求驱动上报电压 | 主控发出查询后，再用battery看结果 |
| `driver read` | 清旧配置记录，请求驱动回复已有配置 | 只允许停车且无电机传输故障时查询，不写持久参数 |
| `driver info` | 查看收到的普通文本配置 | 版本、类型、死区、线数、减速比和轮径；fields表示收齐哪些项，不表示参数正确 |
| `driver safety` | 查看已知驱动行为及许可缺项 | SPD为mm/s、断命令保持末值、无超时配置；显示software_stop_verified及轮径是否匹配 |
| `driver reply` | 查看最近一条完整的未知`$...#`回复原文 | 不包含普通配置行；不是参数已正确的证明 |
| `stop` | 取消底盘、标定及机械臂许可，底盘PWM0、舵机冻结 | 不清除通信故障；之后仍需重新回中、新按START |
| `cal arm` | 申请一次单轮标定许可 | 回中条件满足后进入准备状态，许可5秒后过期 |
| `cal pulse 1 50 200` | M1给一次+50原始PWM参数、持续200ms | 通道1～4；允许负号；只执行一次，不自动重复 |
| `cal cancel` | 取消标定并停车 | 与stop采用同一停车入口 |

每条指令回复都以`reply `开头。当前默认版下载后的`version`预期返回`reply version=rm_rct6-bench-20261104-r9-safe`，PS2版后缀为`-ps2`，`status`返回`reply state=...`。最后确认的主板回复仍为旧版`rm_rct6-chassis-20261023-r1`。开机版本行和每500ms的自动状态行没有这个前缀，查询结果按完整对应回复判定。

`reply OK`说明主控接受了指令或发出了查询，不代表驱动已执行，更不是实物验收通过。`reply ERR`后的文字解释拒绝原因。电脑的Command模式要求恰好一条完整、与本次指令对应的回复；缺少换行、出现多条回复或只收到自动日志都会报失败。新固件与此版本的board.ps1应配套使用；旧固件没有reply前缀时，Command模式会拒绝把它算作成功。

资料包的PC教程截图和固件格式字符串已明确read_flash使用普通文本行。自r4起单独接收六项配置，保留原来的`driver reply`查询未知封包；实际驱动回读尚未测试。停车后先发`driver read`，等待驱动回复，再发`driver info`。若还没收全可再查info，不必反复read清空记录。

机械臂的`arm`查询和轮子标定的`cal arm`是两个不同命令。机械臂由L2模式下的新START许可、R2使能和右Y控制；进入L2模式会取消轮子标定，不能同时运行。`stop`同时冻结最后已写入的舵机脉宽并撤销机械臂许可，不让承重机构自动卸力。`arm issues/inhibit`与原底盘配置位图不同，完整表见[ARM_CONTROL.md](ARM_CONTROL.md)。默认机械臂配置未填写，`arm issues=0x7F`、输出掩码0是预期。

`fields=0x3F`表示六项都已收到；0x01版本、0x02类型、0x04死区、0x08磁环线数、0x10减速比、0x20轮径。没有对应位时，显示的0或none不能当作真实配置。`age_ms`是最后一个合法配置字段的年龄，不是每项分别的时间，也不是查询事务成功标志。`diameter_mm`是驱动自己的Flash轮径，应人工核对是否与本车80mm一致。info只读，不会刷新电机健康、修改verified或写驱动Flash；详细字段、来源和接收限制见[DRIVER_REFERENCE.md](DRIVER_REFERENCE.md)。

## config缺项怎么看

这里的issues与status的inhibit是两个不同的表。

| issues位值 | 说明 |
|---|---|
| 0x01 | 车轮和车体尺寸未确认 |
| 0x02 | 轮序/正反方向未确认 |
| 0x04 | 驱动电机参数未确认 |
| 0x08 | PS2供电、逻辑电平和接线未确认 |
| 0x10 | 无线失联停车未确认 |
| 0x20 | SELECT/电脑stop的软件停车检查尚未完成，见software_stop_verified |
| 0x40 | 速度单位未确认 |
| 0x80 | 尺寸、方向、限速或时间等数值还不合法 |

数值可以叠加，r6默认是0xBF、speed_unit=1：单位已确认，所以清除0x40，其余缺项不变。历史r1/r4/r5的0xFF回复保留为历史。真正量过、核实过的项，去`src/board_config.c`填写并重新编译；不能为了让车动直接全改true。行驶还额外要求driver safety中的diameter_match=1，即驱动回读轮径与主控当前80mm一致；它不包含在静态config位图中。

无电机负载联调时依次发送driver read、等回复、driver info、driver safety。r8显示mm_s、command_loss=hold_last、timeout_config=unsupported、software_stop_verified=0/1及diameter_match=0/1。按用户本轮要求，软件停车检查替代之前独立停车门禁，分别检查SELECT/电脑stop撤销许可并生成PWM0，再记录验收。主控停机或TX断线时，软件停车命令可能无法送达，人工架空联调中带动力保持通信线接好。

## 单轮标定是怎样限制的

标定默认关闭。开放前完成PS2接线、无线行为及软件停车检查，再启用`calibration_enabled`。它可用于填写轮序和方向，几何/速度换算留在普通行驶阶段检查。按用户2026-11-04确认，今晚以SELECT/电脑stop急停、人工看护、四轮架空进行。主控正常运行且命令TX畅通时才能把PWM0送达，异常时先隔离电机动力再排查。

申请许可前，摇杆回中且START/SELECT松开至少300ms，手柄和编码器反馈都需新鲜，不能有通信故障或控制停顿。`cal arm`只准备，不转轮；之后5秒内发送一次`cal pulse`。

默认参数幅度最多100、时长最多200ms。持续时间从首次生成非零输出开始计算；请求后等待达到100ms还没开始会取消，不会延后突然动作。配置代码还设有绝对上限：幅度300、时长500ms。驱动会受自己的死区补偿设置影响，**原始PWM参数100不等于100/3600的实际占空比，也不能据此保证功率很低**。

一个脉冲只选择一个驱动接口。许可不能叠加、不能用重复arm延长，脉冲结束后重新回中并申请。推摇杆、按START/SELECT、急停、反馈超时、串口故障或控制停顿都会取消。主控约20ms检查一次并发PWM0，实物停轮时间在架空测试中记录。

state=4表示正在单轮标定；cal=1表示已准备，cal=2表示执行脉冲，cal=0表示未在标定。正常行驶与标定互斥；标定结束不会自己转成正常行驶。

## 格式和错误恢复

指令区分大小写，使用表中的小写。整行最多63个ASCII字节，末尾加CR、LF或CRLF；CRLF只算一行。超过长度、出现控制字符、参数溢出或未知指令都会拒绝。

命令最后一个字节进入缓存超过200ms，或整行从首字节到处理超过2秒，就当旧命令拒绝。使用电脑工具一次发送整行即可。没有原始电机命令透传，也没有远程修改verified的指令。

调试UART接收出错或接收缓存满后，会丢弃旧指令并关闭接收中断；发送回复失败也会锁住电脑指令入口。标定许可取消，机械臂冻结并锁存IO故障：回复失败后立即处理，读手柄后和真正写输出前还会检查。即使非零电机PWM文字或舵机新目标已经算好，也会在发现故障后撤销，不把旧目标补发出去。

普通行驶仍由PS2安全流程负责；恢复电脑指令功能需排查后复位主控。电机UART的故障单独记录，同样不能靠stop或新好包清除。新回归用例和构建结果见[修复验证记录](reports/REVIEW_FIXES_2026-10-22.md)。
