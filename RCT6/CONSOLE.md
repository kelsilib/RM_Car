# 电脑串口指令说明

这些指令走板载CH340连接的USART1，115200、8N1、无流控。电机协议仍走USART2，两边不能混接。

没有主板时，先运行 `.\build.ps1 -Test`、`.\board.ps1 -Mode Test` 和 `.\board.ps1 -Mode Verify`。它们只在电脑上运行，不需要连接设备。

有板后，`board.ps1 -Mode Terminal -Port COM7` 可以打开交互终端，把COM7换成实际端口。工具先收齐你输入的一整行，再发给主控；输入`exit`只退出电脑终端。单次指令可用 `board.ps1 -Mode Command -Port COM7 -Command 'ps2'`。2026-10-25用户在COM5的Terminal中取得version/config完整reply回复，确认这两条查询的实际双向收发；其他指令和Command模式仍按实际测试记录，不能自动认定全部通过。详见[单板实测记录](reports/USB_ISP_2026-10-25.md)。

## 可以发送哪些指令

| 指令 | 做什么 | 怎么读结果 |
|---|---|---|
| `help` | 列出指令 | 不控制电机 |
| `version` | 查看软件编号 | 当前本地构建为`rm_rct6-chassis-60mm-r2`；尚未烧录 |
| `status` | 当前状态和不能动的原因 | state、inhibit沿用周期日志，另外显示cal阶段 |
| `ps2` | 查看手柄 | fwd/left/yaw为千分比：1000表示该方向推满，不是m/s |
| `counts` | 最近MAll的四个原始计数 | 按M1/M2/M3/M4排列；不是左前/右前/左后/右后顺序 |
| `config` | 查看缺项和标定限制 | issues各位见下表；不允许在终端修改验收标志 |
| `output` | 最近生成的四通道目标 | mode=spd时按已确认的mm/s；mode=pwm时是厂商PWM参数 |
| `battery` | 最近收到的电压 | millivolts除1000得到V；seen=0表示还没收到电压包 |
| `driver voltage` | 请求驱动上报电压 | 主控发出查询后，再用battery看结果 |
| `driver read` | 请求驱动回复已有配置 | 只允许停车后查询，不写持久参数 |
| `driver reply` | 查看最近一条完整的未知回复原文 | 用于人工核对配置回复；不是参数已正确的证明 |
| `stop` | 取消普通解锁和标定许可，发送PWM0 | 不清除通信故障；之后仍需重新回中、新按START |
| `cal arm` | 申请一次单轮标定许可 | 回中条件满足后进入准备状态，许可5秒后过期 |
| `cal pulse 1 50 200` | M1给一次+50原始PWM参数、持续200ms | 通道1～4；允许负号；只执行一次，不自动重复 |
| `cal cancel` | 取消标定并停车 | 与stop采用同一停车入口 |

每条指令回复都以`reply `开头。新r2下载后的`version`预期返回`reply version=rm_rct6-chassis-60mm-r2`，`status`返回`reply state=...`；这只是新版本的预期，最后确认的主板回复仍为旧版`rm_rct6-chassis-20261023-r1`。开机版本行和每500ms的自动状态行没有这个前缀；只看到自动日志，不能说明电脑指令已被处理。

`reply OK`说明主控接受了指令或发出了查询，不代表驱动已执行，更不是实物验收通过。`reply ERR`后的文字解释拒绝原因。电脑的Command模式要求恰好一条完整、与本次指令对应的回复；缺少换行、出现多条回复或只收到自动日志都会报失败。新固件与此版本的board.ps1应配套使用；旧固件没有reply前缀时，Command模式会拒绝把它算作成功。

驱动配置回复格式尚未实测，因此只缓存最近一条完整`$...#`未知回复，不猜字段、不自动填写验收项。普通MAll或电压包不会覆盖这段未知回复；没有包头包尾的厂家文本不在此缓存范围内。

## config缺项怎么看

这里的issues与status的inhibit是两个不同的表。

| issues位值 | 说明 |
|---|---|
| 0x01 | 车轮和车体尺寸未确认 |
| 0x02 | 轮序/正反方向未确认 |
| 0x04 | 驱动电机参数未确认 |
| 0x08 | PS2供电、逻辑电平和接线未确认 |
| 0x10 | 无线失联停车未确认 |
| 0x20 | 驱动独立停车保护未确认 |
| 0x40 | 速度单位未确认 |
| 0x80 | 尺寸、方向、限速或时间等数值还不合法 |

数值可以叠加，默认是0xFF。真正量过、核实过的项，去`src/board_config.c`填写并重新编译；不能为了让车动直接全改true。

## 单轮标定是怎样限制的

标定默认关闭。要开放这套接口，必须在配置中明确启用`calibration_enabled`，并完成PS2接线、无线失联和驱动独立停车保护的确认。它不要求先知道轮径、轮序和速度单位，因为用途正是逐轮核对这些数据；不会自动解锁整车行驶。

申请许可前，摇杆回中且START/SELECT松开至少300ms，手柄和编码器反馈都需新鲜，不能有通信故障或控制停顿。`cal arm`只准备，不转轮；之后5秒内发送一次`cal pulse`。

默认参数幅度最多100、时长最多200ms。持续时间从首次生成非零输出开始计算；请求后等待达到100ms还没开始会取消，不会延后突然动作。配置代码还设有绝对上限：幅度300、时长500ms。驱动会受自己的死区补偿设置影响，**原始PWM参数100不等于100/3600的实际占空比，也不能据此保证功率很低**。

一个脉冲只选择一个驱动接口。许可不能叠加、不能用重复arm延长；脉冲结束后必须重新回中并申请。推摇杆、按START/SELECT、急停、反馈超时、串口故障或控制停顿都会取消。开始和结束仍由20ms左右的主循环检查，物理停车效果最终依赖驱动及独立保护；软件时间界限不是已测的机械停止时间。

state=4表示正在单轮标定；cal=1表示已准备，cal=2表示执行脉冲，cal=0表示未在标定。正常行驶与标定互斥；标定结束不会自己转成正常行驶。

## 格式和错误恢复

指令区分大小写，使用表中的小写。整行最多63个ASCII字节，末尾加CR、LF或CRLF；CRLF只算一行。超过长度、出现控制字符、参数溢出或未知指令都会拒绝。

命令最后一个字节进入缓存超过200ms，或整行从首字节到处理超过2秒，就当旧命令拒绝。使用电脑工具一次发送整行即可。没有原始电机命令透传，也没有远程修改verified的指令。

调试UART接收出错或接收缓存满后，会丢弃旧指令并关闭接收中断；发送回复失败也会锁住电脑指令入口。标定许可都会取消：回复失败后立即处理，读手柄后和真正发电机命令前还会检查。即使非零PWM文字已经算好，也会在发现故障后换成PWM0，不把旧文字发出去。

普通行驶仍由PS2安全流程负责；恢复电脑指令功能需排查后复位主控。电机UART的故障单独记录，同样不能靠stop或新好包清除。新回归用例和构建结果见[修复验证记录](reports/REVIEW_FIXES_2026-10-22.md)。
