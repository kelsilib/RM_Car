# 四路驱动主控软件收尾与验证

日期：2026-11-02。当前固件`rm_rct6-driver-final-20261102-r6`。基于Git提交`d1fcb37b4e0640aaf22289fb503d845ec26cc864`及已有未提交的r5机械臂、80mm几何、驱动解析和排线工作继续修改；分支仍为`feat/rct6-ps2-60mm`，实际轮径80mm。没有暂存、提交、推送或烧录。

## 本次新增依据

用户本次补充确认：①SPD为受wdiameter影响的轮缘mm/s，不是输出轴转速；②驱动不会自动停车，没有超时配置项，断命令会一直保持最后SPD/PWM。此处如实记录为用户转述确认，原始厂家回复未附，本轮未连接设备进行复测。已有厂商文件和来源哈希保持，详见[资料依据](../DRIVER_REFERENCE.md)。

## 最终实现

| 修改 | 结果与边界 |
|---|---|
| SPD单位 | 默认`RM_SPEED_MM_S`，沿用轮缘mm/s换算与±1000指令范围；不额外转为rpm，不擅自修改电机PID |
| 驱动轮径回读门禁 | 必须收到合法轮径字段，与`radius_m×2000`按三位小数一致，才可能输出行驶速度。当前期望80.000mm；缺失、非法或67mm等不一致值均输出PWM0 |
| 失联能力与验收项 | 删除含义错误的`driver_failsafe_verified`，改为`independent_stop_verified=false`；普通行驶、单轮PWM标定都要求独立停车路径验收，未放行运动 |
| 新只读诊断 | `driver safety`显示`spd_unit=mm_s command_loss=hold_last timeout_config=unsupported independent_stop=0 diameter_match=0/1`；不写Flash、不更改验收标志、不发送不存在的超时命令 |
| 恢复行为 | 轮径错误时取消普通解锁；匹配恢复也不能凭按住START自动恢复，需要回中、松键、新按START。错误字段不会覆盖人工验收记录 |
| 既有功能 | 七路MG995控制、PS2时序/按键、HAL适配、时钟、引脚、80mm/CAD尺寸和车头均保留；机械臂仍默认关闭 |

`config`默认预期从旧0xFF变为**0xBF、speed_unit=1**，只清除“速度单位未知”位。独立停车、电机参数、实物方向和其他未验收位保持。运行期轮径比较结果由`driver safety`观察，不混入纯配置位图。

单轮PWM标定不依赖已知尺寸来换算，因此不要求轮径门禁，但同样不能绕过独立停车保护。仅发送短脉冲也可能在TX断线后被驱动无限保持，默认标定继续关闭。

## 完成范围与上板边界

驱动主控端协议、单位换算、诊断、轮径门禁和软件故障处理已完成本轮验证。驱动内部只提供HEX，没有取得内部源代码，也没有新增或烧入所谓“驱动超时固件”。本轮没有自动写wdiameter、mtype、线数、减速比或PID，没有原始非零命令透传。

**仍不能开放电机运动：本驱动无自动停车，必须落实另外的独立停车路径。** 主控继续运行且TX可达时可以尝试发PWM0；主控停机、复位或TX断线时，PWM0可能无法送达。MAll新鲜、HAL发送成功或主控心跳都不能证明末值已取消。外部路径须覆盖这些故障，并在恢复后禁止自动重新供动力；仅有人工开关不构成自动失联保护。具体器件、额定值、控制线和延迟未给出，不擅自分配GPIO或声称硬件已实现。功能要求见[独立停车说明](../DRIVER_REFERENCE.md#6-驱动没有超时停车怎样处理)。

当前可做的下一步是按[USB ISP流程](../USB_ISP.md)进行断动力单板下载，核对version和config；随后在无电机负载条件下接UART，执行driver read、等待、driver info、driver safety。驱动晚启动导致首次read_flash没有回复时，用停车后的driver read重新请求；上传开关重试不等于重新读配置。独立停车硬件、轮序/方向、参数与PS2验收完成前，不开展转轮标定或整车运动。
